Review Git cleanliness, remote hashes and complete installed-to-target diffs.
All tracked executable application files outside test/operator utilities must
match, including TIX guard/policy/hooks and Restaurant hooks/finalizer. Existing
markers are expected; this is not the earlier unmarked-account activation pilot.

of this update: those receipts pin the older source commits by design.

Create per-app evidence branches before editing. Install only the exact approved
maintenance pins, not these later evidence commits. Principal refs do not move.

this does not edit repository configuration or run unreviewed checkout automation.
Retain original commits and the minimarket documentation branch. No dependency
installation, build, migration, import_doc, cache reset or service command is needed.

## Verification

Use an existing secret-safe local TOML reader in memory only; no credential or
account identity is printed or copied into evidence. Connect only to loopback
HTTP with the approved site Host header. No redirects, retries, provider calls,
MCP wrapper or audit POST. Per-socket timeouts, response size limits and a process
deadline bound each verification run.

Check guest ping, two name-only minimal resources and four harmless negative
GET requests: identity route, duplicate limit, inert method-override header and
limit 101 must return the exact guard denial. Health remains an accepted warning
if only the reviewed inherited-permission/action-disabled warnings are present.
Use mapped field metadata to select minimal fields for company-filtered tables,
active reservations, recent table orders and fulfillment records. Limit each
list to at most 20 (or its lower mapped cap); return only counts and known enum
counts, never business document names, contact/address values or response bodies.
The before/after reads validate availability, not immutable business counts.
The pre-existing intermittent health timeout is a separate unpassed diagnostic,
not a gate to hide or retry until green. For this runtime-identical alignment,
all seven required GET/denial probes and all four resource reads must pass;
a health timeout alone does not permit wider changes or certify general health.
Any other failed required read or unexpected health error still stops alignment.
No POST, document creation, provider request or live action is a test target.

After installing Restaurant, recheck cleanliness, runtime blob equality and
ordinary reads before TIX. After the pair, run the versioned offline runner from
installed TIX against installed Restaurant under -I -S -B with raw dependencies;
its guards forbid site/DB/Redis/network/process use. Run its 25 stdlib self-tests.
Fresh imports/source hashes are not proof every long-lived worker reloaded.
A development server may independently react to filesystem changes; no explicit
service or reload action is authorized or performed here.

## Recovery

failed preflight. Preserve intermediate evidence. If recovery is required by a
regression introduced by this checkout, recheck concurrent edits and return only
to the recorded original pair: TIX 41d8d21669ba9f149faac70d8b68fafcbff6fe80 and
Restaurant c1333a8bb7d557e1eb8af27c5f3384e86e73f467. Both already include the guard.

shared All rights, or change settings/services as an automatic recovery step.
No generated business data or database migration needs reversal. Evidence branches
remain separate and remotely backed up; archival/merge are not implicit.
